# 2026-10-19 — IO rail load

**Goal.** Give L2F and L3F the 30 mA load from stock's
`qcom,vdd-wlan-io12-config` and `qcom,vdd-wlan-io-config`, so those
LDOs leave low-power mode, and see if `fw_caps` grows an aux bit.
**Phone.** OnePlus 13 CPH2653. One restart. The screen went dark
and the desktop came back.
**Kernel.** `6.16.0-gb3ee311dab85`
**Result.** Fail. Both LDOs are in high-power mode at 30 mA.
`fw_caps` is still `0xf`. The firmware enters RDDM on the same
aux-MAC assert. No `wlan`.

## What stock asks for

The peach node sets load 0 on S5F, S4D, S7I and S3G. L2F and L3F
are `0x7530` (30000 µA). On pm8550ve those two are nLDOs whose
high-power threshold is 30000 µA. `pwrseq-qcom-wcn` enables them
with no load, so they stay in the low-power initial mode. The
peach node has no `clocks` property. `RF_CLK1` was already on.

`regulator_set_load()` does not change the mode until that
consumer has enabled the rail. The first module returned 0 and
left both LDOs idle. Enabling them as well moved both to
high-power mode: 1.200 V and 1.800 V, `requested_microamps` 30000.

## What the phone did

The sysrq restart found slot A unbootable with zero tries.
`fastboot set_active a`, already the current slot, restored
seven tries. Slot B stayed unbootable. The desktop and
`17cb:110e` were up before ath12k was loaded.

With the two LDOs in high-power mode, the probe matched the
previous one. Host feature list `0x58`. `fw_caps` `0xf`.
Board response `host bdf data 0x1`, HW_XPA set. Aux QMI
error 90. RDDM about 160 ms later. The new dump repeats
`Asserted in:0x1a9046c:0x1a90c80, line#192` and
`whal_aux_mac_trigger_wakeup`. Mode 0 timed out (`-110`).
Hyprland stayed active. oops count 0. ath12k is bound.
Do not load it again on this boot.

The switcher voltages were left where `pwrseq` puts them
(S5F and S4D at 852 mV, S7I at 1.224 V). Raising those was
an earlier probe and still reset the firmware.
