# 2026-10-17 — stock peach firmware reaches AMSS

**Goal.** Get the Wi-Fi chip out of PBL.
**Phone.** OnePlus 13 CPH2653. The desktop stayed up.
**Kernel.** `6.16.0-gb3ee311dab85`
**Result.** Stock `peach/amss20.bin` now runs. QMI reports the
firmware build. There is still no `wlan` interface. A second load
on the same boot oopsed. ath12k is bound. Do not unload it and do
not reboot this boot from software.

## What the file is

`amss20.bin` (6840384 bytes, copied read-only from `modem_a`, not
in git) is two ELF images:

- offset 0, ELF32, machine 40 (ARM). The loadable bytes end near
  190 KiB. This is the SBL.
- offset 512 KiB, a second ELF32. This is the WLAN firmware.

OnePlus CNSS2 sets MHI's `tme_supported_image` for this PCI id.
That flag does not change the BHI step. It tells BHIe to send only
the bytes after `sbl_size`. The TME-L ELF (`tmel_peach_20.elf`) is
a later QMI download, from `cnss_fw_mem_ready_hdlr`, after the
firmware is already up. Sending it as `amss.bin` is rejected
(`0xef010700`).

## What happened

BHI of the first 512 KiB returns success, and `BHI_EXECENV` is
already `1` (SBL) before the host is waiting on an event-ring
packet. The packet never comes, so the old 90 s wait was the host
missing a transition that had already happened. Continuing from
the register, and sending the second ELF over BHIe (6316096 bytes
from offset 524288), gets `BHI_EXECENV` to `2` (AMSS). ath12k then
prints:

```
chip_id 0x2 chip_family 0x4 board_id 0xff soc_id 0x40210200
fw_version 0x10097fff fw_build_timestamp 2025-11-18 09:48
fw_build_id QC_IMAGE_VERSION_STRING=WLAN.GNG.1.0-03342-QCAGNGSWPL_V1.0_V2.0_SILICONZ-1.81206.153
```

The firmware also asks for memory region type 11. This tree did
not allocate it (`memory type 11 not supported`). Upstream calls
that region `LPASS_SHARED_V01_REGION_TYPE` and allocates it with
the other host regions. The WLAN mode request then timed out
(`qmi failed set mode request, mode: 0, err = -110`). The
allocation is in the tree and has not been retested.

## The second load

`rmmod ath12k` worked after that timeout (`used by 0`). Loading
the module again oopsed in `mhi_queue_skb` from a QMI server-arrive
work item, before MHI had finished power-on, and the SMMU reported
a context fault (SID `0x1401`, IOVA `0xf9847080`). Mission mode
then logged a duplicate `mhi0_IPCR` device. The desktop stayed up.
ath12k is still bound. Leave it there until a person is at the
phone. Recovery if the session dies is `sync` and
`echo b > /proc/sysrq-trigger`, not `systemctl reboot`.

ath12k stays out of the boot service.
