# 2026-10-20: Wi-Fi scans (ath12k on peach)

## Result

`wlan0` registers (udev renames it `wlp1s0`), `ip link set wlp1s0 up`
works, and `iw dev wlp1s0 scan` lists 11 access points on 2.4 GHz
(15:15 CEST). Connecting was not tried; it needs the owner's Wi-Fi
password.

## Root cause

Three host-side mismatches, found and fixed in this order, one per boot:

1. **`CNSS_QDSS_CFG_MISS` (host cap feature bit 3).** The old host cap
   told the firmware the QDSS trace config was missing. The firmware then
   started init early, rejected aux uCode and the QDSS config with QMI
   error 90 (incompatible state), and asserted in
   `whal_aux_mac_trigger_wakeup`. Stock sends the QDSS config, and the
   ROCKNIX SM8750 WCN7860 port drops this bit. With it cleared (feature
   list `0x50`: `PCIE_PERST_NO_PULL | AUX_UC_SUPPORT`) aux and QDSS are
   accepted, `FW_READY` arrives, WMI is ready and `wlan0` registers.
   The TME-Lite `err 83` is harmless: stock gets it too.
2. **rfkill.** The WCN7850 parameters ask the firmware to watch GPIO 48
   as an rfkill pin. Peach on dodge has no such line, so the radio came up
   `Hard blocked: yes`. ath12k now skips rfkill config for PCI id
   `0x110e` (ROCKNIX sets `rfkill_pin 0` for the same reason).
3. **Single-phy WMI handling.** With rfkill clear, `ip link up` failed
   with `-EAGAIN`: `WMI_PDEV_SET_PARAM` (16387) timed out waiting for
   credits and `fail to start mac operations`. Backporting the generic
   fixes from the upstream QCC2072 series fixed it: choose the preferred
   hw mode with `<=` (so a mode that ties fills `pref_hw_mode_caps`),
   parse MAC/PHY caps for the preferred mode only, and send at most 58
   channels per scan channel-list command. Peach reports 2 hw modes; the
   driver now picks mode 5 with phy map `0x3`.
   All three went in on one boot, so it is not known which one alone
   was needed.

## Attempts

| # | Change (one per boot) | Result |
|---|---|---|
| 1 | Clear `QDSS_CFG_MISS` in host cap | Aux and QDSS accepted, FW ready, `wlan0` registered. rfkill hard-blocked. |
| 2 | No rfkill GPIO on `0x110e` | rfkill clear. `ip link up` gives `EAGAIN`, WMI 16387 timeout, mac start fails. |
| 3 | Single-phy hw mode, MAC/PHY caps, 58 channels per chan-list command | `ip link up` works, scan finds 11 BSS on 2.4 GHz. |

## Method

- Consulted Claude first. It agreed: try mission mode first, keep wlan
  unmanaged by NetworkManager, and watch for HAL mismatches.
- Compared with the upstream QCC2072 series (ath-next, Jan 2026), the
  ROCKNIX SM8750 WCN7860 patches 0039-0044 and linux-next `wmi.c`.
- Compared with the stock rooted capture (read-only). Stock also gets
  TME `err 83`, then loads regdb, BDF, `phy_ucode20`, `aux_ucode20` and
  `qdss_trace_config_v2.cfg`.
- ath12k is loaded once per boot. Each test boots, loads the
  prerequisite modules from `/usr/local/lib/omamobile`, loads
  `ath12k.ko` once, sets the link up and scans.

## Setup on the phone (not in git)

- `/usr/local/lib/omamobile/ath12k.ko` comes from the local kernel branch
  `omamobile-dodge`.
- Firmware is in `/lib/firmware/ath12k/WCN7850/hw2.0/`, from the owner's
  image. It is never committed.
- NetworkManager leaves `wlan*` and `wlp*` unmanaged
  (`/etc/NetworkManager/conf.d/90-dodge-wlan-unmanaged.conf`).
- ath12k is not loaded at boot yet.

## Open

- Only 2.4 GHz was seen in one 40 s scan. The 5 and 6 GHz channels are
  enabled, but under the world regdomain they are passive scan.
  "Failed to set the requested Country regulatory setting" appears twice.
- The hw_params are still WCN7850 with the `0x3278` window. Upstream
  QCC2072 uses different TCL, REO, WBM, PCIe and qrtr register offsets and
  a different HAL. Data traffic may need them; it has not been tested.
- The MAC address is the firmware placeholder. The real one is not read
  yet.
- Loading at boot and NetworkManager management are not done yet.
