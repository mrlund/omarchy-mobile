# 2026-10-15 — rooted capture, screen on

**Goal.** Read the live stock state with Magisk `su`, screen on. Do not
change the panel.
**Phone.** CPH2653, build `CPH2653_16.0.10.501(EX01)`, slot `_a`,
verified boot `orange`. `magiskd` is running.
**Kernel.** No kernel of ours.
**Result.** The screen-on capture is saved. The live DTB decompiles.
Debugfs summaries are missing. The screen-off capture is not done.

## What we did

The shell's `su -c id -u` returned 0. `DEVICE=dodge bin/omamobile
capture dodge-cph2653/rooted-2026-10-15-on`. The first run stopped
because `cat /proc/cmdline` is denied for uid 2000 and the script
treated that as fatal. The script now keeps going, and the root path
reads cmdline itself. The second run finished.

## What happened

The directory is
`~/android/reference/dodge-cph2653/rooted-2026-10-15-on/`. It stays out
of git. `live.dtb` is 1638203 bytes and decompiles (47314 lines). Its
root is:

- `model` "Qualcomm Technologies, Inc. Sun MTP,dodge"
- `qcom,board-id` `<0x40008 0x00>`
- `qcom,msm-id` all eight sun/sunp pairs, in this order: `<0x100026a
  0x20000>`, `<0x27f 0x10000>`, `<0x26a 0x10000>`, `<0x27f 0x20000>`,
  `<0x26a 0x20000>`, `<0x100027f 0x10000>`, `<0x100026a 0x10000>`,
  `<0x100027f 0x20000>`

The model string is the one on the non-T0 dodge overlays. The live
property still lists every pair, so nothing is collapsed.

`/sys/kernel/debug` exists and debugfs is not mounted. `clk_summary`,
`regulator_summary`, `pinmux-pins` and `gpio` are absent.
`/vendor/firmware_mnt` lists `image` and `verinfo`. `dmesg` and the
partition size list were saved. No regmap registers, `devmem`, or
`persist` reads.

## Learning

Copy `qcom,board-id = <0x40008 0x00>` and the eight msm-id pairs into
the mainline DTB when that edit is made. Do not pick one pair. The
screen-off capture is the same command with `-off`, after the panel is
turned off by hand. Mounting debugfs would be a separate step.
