# 2026-10-19 — fuel gauge bus and PMIC temperature

**Goal.** See whether the running tree already exposes a battery
percent, and turn on the PMIC temperature alarms if they only
need their module.
**Phone.** OnePlus 13 CPH2653. No restart. The desktop stayed up.
**Kernel.** `6.16.0-gb3ee311dab85`
**Result.** No percent. Address `0x55` does not answer. The PMIC
temperature alarms probe and all sit in stage 0.

## What we did

`power_supply` was empty because `i2c-qcom-geni` is a module in
the held tree and nothing loads it. The live DTB enables two
I2C hubs: `98c000` with `ti,bq27541` at `0x55`, and `9a4000`
with the hall sensor. `CONFIG_AK09970` is off, so the hall node
does not bind.

`insmod` of `i2c-qcom-geni.ko` brought both buses up at 100 kHz.
The gauge driver bound and every property read returned `-ENXIO`.
`present` was 0. After unbinding that client, a quick scan of
bus 0 found one address, `0x36`. A read of that address, and a
register read at 0, both returned `0xffff`. Addresses `0x55`,
`0x50` and `0x48` NACK.

`qcom-spmi-temp-alarm.ko` then bound the ten SPMI alarm nodes.
Nine zones report. The tenth name was the gauge, which is gone
after the unbind.

## What it means

Stock's gauge node is `oplus,virtual_gauge`, and its
`oplus,gauge_ic` is `oplus_adsp_gauge`. The design capacity in
that node is 5610 mAh, or 5920 mAh on the `silicon_p_770`
variant. Percent does not come from `ti,bq27541` at `0x55`.
The mainline `simple-battery` node sets
`voltage-min-design-microvolt` to 6.3 V, which matches the
stock "dual cells" charger path, not a single 1S pack.

`qcom-spmi-temp-alarm` uses 37.0 °C as the value for stage 0.
All nine PMICs reported that, so every alarm is below its first
trip. It is not a measured die temperature.

Neither module is on the boot path. ath12k was left bound.
Hyprland stayed active.
