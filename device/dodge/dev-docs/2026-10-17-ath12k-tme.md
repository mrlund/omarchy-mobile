# 2026-10-17 — TME-Lite and the mode timeout

**Goal.** Find who has already brought up this Wi-Fi chip, and try
the step they say fixes the WLAN mode timeout.
**Phone.** OnePlus 13 CPH2653. The desktop stayed up. Several
restarts were `sync` then `echo b > /proc/sysrq-trigger`, because
a second `insmod` on the same boot oopses.
**Kernel.** `6.16.0-gb3ee311dab85`
**Result.** The open port of the same PCI id does the step stock
does. The firmware rejects that step (`result 1, err 83`), then
resets, and the mode request times out. No `wlan` interface.
ath12k is bound. Do not load it again on this boot.

## Where the sequence comes from

The OnePlus 13s (pagani, SM8750, PCI `17cb:110e`) mainline tree
has an ath12k peach series:
<https://github.com/renhiyama/pagani-linux/commit/c49d202>.
It says a missing TME-Lite download faults the secured PHY init
and the set-mode request returns `-110`. Stock CNSS2 does the
same download in `cnss_fw_mem_ready_hdlr`, after target
capabilities and before board data: `tmel_peach_20.elf` in DMA
memory, then `QMI_WLFW_TME_LITE_INFO_REQ` (`0x005B`) with the
address and size. That port also skips a separate M3 file (peach
carries M3 inside `amss`) and sends WLAN mode 7 (cold-boot
calibration) before mission mode.

postmarketOS lists SM8750 Wi-Fi as untested. Upstream ath12k
still has no `0x110e`.

## What the phone did

`tmel_peach_20.elf` (55204 bytes, from `modem_a`, not in git) is
requested and the QMI message is answered:

```
qmi TME-Lite info request failed, result: 1 err: 83
```

About 200 ms later the driver logs `ignore reset dev flags`,
which is the firmware-crash path firing before bring-up has
finished. Cold-boot mode 7 then times out the same way mode 0 did.

The stock board file was sent on a later boot. `board.bin` is the
ELF from the modem image (125420 bytes). The upstream WCN7850
`board-2.bin` was moved aside so it could not be chosen for board
id `0xff`. There is no `regdb.bin`, so that download returns
`-ENOENT` and is ignored for this PCI id. The log then shows
`qmi board data len 125420 type 1`, and the firmware still resets.

A second `insmod` without a restart oopses in `mhi_queue_skb`
from the QMI server-arrive work. The first probe of a boot does
not. ath12k stays out of the boot service.
