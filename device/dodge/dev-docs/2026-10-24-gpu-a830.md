# 2026-10-24: Adreno 830 GPU on dodge (7.3 trial `7.3.0-rc6-dodge-gpu1`)

The flashed default (7.3.0-rc6-dodge-s1) was not changed. All GPU work ran as
one-shot `fastboot boot` trials without `dodge.flashed`, so the hard deadline
stayed armed.

## Why there was no GPU

- 7.3-rc6 has no A830 entry in the msm catalog. The upstream series
  "drm/msm: Support for Adreno 830 GPU" (Akhil P Oommen, 2026-08-08) has not
  been merged.
- `sm8750.dtsi` has no gpucc/gxclkctl/adreno-smmu/GPU/GMU nodes. The clock
  drivers exist (`gpucc-sm8750`, `gxclkctl-kaanapali`, both behind
  `CONFIG_SM_GPUCC_8750`).
- 7.3-rc6 already has the GX GDSC `.power_off` and `a6xx_gmu_gxpd_get/put`
  changes (ROCKNIX 0050/0051).

## Kernel changes (local trial branch; exported here as 0054-0058)

| patch | what |
| --- | --- |
| 0054 | sm8750: gpucc@3d90000, gxclkctl@3d64000, adreno_smmu@3da0000 (ROCKNIX 0033) |
| 0055 | sm8750: gpu@3d00000 (`qcom,adreno-44050000`), gmu@3d37000 (`qcom,adreno-gmu-830.1`), zap region (ROCKNIX 0038) |
| 0056 | drm/msm: A830 catalog entry, chip id 0x44050000, `gen80000_{sqe.fw,gmu.bin,aqe.fw}` (ROCKNIX 0049) |
| 0057 | dodge: `&gpu` okay, zap `firmware-name = "qcom/sm8750/OnePlus/gen80000_zap.mbn"` |
| 0058 | sm8750: GPU reg 0x40000 -> 0x60000 so `gpu->mmio + 0x50000` (A8xx RSCC) is mapped |

Config: `dodge-73-gpu.config` (`CONFIG_SM_GPUCC_8750=y`). The held modules
never autoload, and msm binds the GPU when it is insmodded, so the clock
controllers have to be built in.

## Firmware (not in this repo)

| phone path | source |
| --- | --- |
| `/lib/firmware/qcom/gen80000_sqe.fw` | linux-firmware |
| `/lib/firmware/qcom/gen80000_gmu.bin` | linux-firmware (identical to stock) |
| `/lib/firmware/qcom/gen80000_aqe.fw` | linux-firmware |
| `/lib/firmware/qcom/sm8750/OnePlus/gen80000_zap.mbn` | stock `vendor` partition of the CPH2653 16.0.10.501 OTA (`firmware/gen80000_zap.mbn`; OEM-signed) |

The linux-firmware `qcom/sm8750/gen80000_zap.mbn` is Qualcomm-signed, so it
most likely will not authenticate on a retail phone. The OEM zap comes from the
OTA's vendor image: payload-dumper-go, then `fsck.erofs --extract`. modem_a has
no zap file.

## Mesa

Mesa 26.2.4 on the phone (`msm_dri.so`, `kgsl_dri.so`, libgallium) lists
GPU id `0xffff44050000` "Adreno (TM) 830". That matches the kernel chip id
0x44050000. Mesa main also adds `0xffff44050001`; stock kgsl reports
0x44050001 (v2 silicon). There is no `msm_dpu_dri.so`, so the trial keeps
the default `separate_gpu_kms=N`, which gives one combined card1. The phone
has no Vulkan ICD and no eglinfo/glmark2/vkcube.

## Trial gpu1a (17:32 CEST)

- The module tree and overlay are `7.3.0-rc6-dodge-gpu1` (s1 overlay copied,
  with gpu1 .ko files on top).
- `ssh` was up at t=39 s. adreno 3d00000.gpu bound into msm_dpu.
  `gen80000_sqe/gmu/aqe` loaded, followed by "Loaded GMU firmware v5.1.25".
  The GPU devfreq OPPs run from 160 to 1100 MHz.
- **Oops** at 9.2 s in the pm workqueue: `a6xx_rpmh_stop+0x94`, from
  `a6xx_gmu_stop` and then `adreno_runtime_suspend`. It was a paging fault at
  `gpu->mmio + 0x50010`. The GPU node mapped only 0x40000, but the A8xx RSCC is
  at GPU base + 0x50000 (stock kgsl: `rscc` 0x3d50000 size 0x10000). Patch 0058
  fixes this.
- The zap was not exercised: it loads at the first GPU open, and the oops came
  first.
- The display was unaffected: card1-DSI-1 connected/On, txfail 0, Hyprland
  running.
- `systemctl reboot` at t=61 s **hung in shutdown**, with USB networking
  still answering ping and sshd stopped. This is likely the oopsed runtime-PM
  worker blocking GPU teardown. As of 17:44 CEST it was still hung: ping up, no ssh, no fastboot, and the deadline did not fire because systemd was already in shutdown. It needs a hands-on forced reboot (hold power + volume up), which lands on the flashed s1.
