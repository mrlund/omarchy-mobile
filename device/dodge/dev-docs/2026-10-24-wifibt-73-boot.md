## Wi-Fi: where it stops

- PCIe link is up and ath12k_wifi7_pci binds 17cb:110e as "wcn7860 hw2.0".
- MHI power-on, then BHI of the 512 KiB SBL waits the full 90 s and returns
  -EIO with pm_state = LD_ERR_FATAL_DETECT.
- The register dump on wifibt2 shows BHI_EXECENV = 1 (SBL) and BHI_STATUS
  bits 31:30 = success. So the device accepted the SBL; the host was never
  woken.
- `mhi_fw_load_bhi`, `ath12k_pci_power_up`, `ath12k_pci_sw_reset` and the
  ath12k MHI setup are the same on 6.16 and 7.3, apart from the config
  tables, which moved to wifi7/. On 6.16 the same step takes under 50 ms.
- Leading hypothesis: the MHI MSI is not delivered on 7.3. Next step is to
  compare `/proc/interrupts` and the PCIe MSI path.
- QMI is never reached, so the qrtr_node_id lead (0x1e03300 vs 0x1E03164)
  is not what stops this boot. That register is also only written with
  FW_FEATURE_MULTI_QRTR_ID.

The full facts are in the host log `2026-10-24-p73-wifi-bhi-facts.md` (not
committed).

## Update 14:05 CEST: root cause found and fixed (patch 0052)

**Root cause:** 7.3 `sm8750.dtsi` gives `apps_smmu` `#iommu-cells = <2>`, so
pcie0's `iommu-map` has 5 cells per entry (`<rid &apps_smmu sid 0x0 len>`).
`qcom_pcie_config_sid_1_9_0()` assumed 4-cell entries:
- The endpoint (BDF 0x100) got no PARF BDF_TO_SID entry, so its TLPs used
  the base SID 0x1400 (the root port's).
- DMA still worked, because the root port and the endpoint share an SMMU
  domain.
- The GICv3 ITS DeviceID comes from that SID, so the endpoint's MSIs arrived
  as DeviceID 0x1400. EventID 0 (the endpoint's BHI vector) fired the root
  port's PME/AER LPI instead, which counted 2 on 7.3 and 0 on 6.16. All
  other vectors were dropped.

**Fix:** `kernel-7.3/0052` reads `#iommu-cells` from the IOMMU node and steps
through the map at 3 + cells. It is an upstream candidate, since upstream
sm8750 has the same DT. Not sent.
