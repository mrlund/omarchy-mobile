# 2026-10-17 — host DMA window and memory type 11

**Goal.** After stock rails and switch pins still got TME-Lite
error 83, send the host DMA window in the host-capability
message and record every firmware memory segment.
**Phone.** OnePlus 13 CPH2653. One restart. Desktop stayed up.
**Kernel.** `6.16.0-gb3ee311dab85`, module from `945d7c2bf`.
**Result.** Fail. Advertising the stage-1 aperture made the
firmware reset before it acknowledged the memory response.
Type 11 was requested and was given a DMA address.

## What the phone did

Host cap logged `ddr range 0x0 size 0x1000000000` (36-bit
stage-1 aperture). The firmware then asked for three segments,
and each got an address:

```
qmi mem req seg[0] type 1 size 7405568
qmi mem req seg[1] type 4 size 4145152
qmi mem req seg[2] type 11 size 4096
qmi mem seg[0] type 1 size 7405568 addr 0x00000000fe800000
qmi mem seg[1] type 4 size 4145152 addr 0x00000000fe400000
qmi mem seg[2] type 11 size 4096 addr 0x00000000ff07a000
```

About 150 ms later: `ignore reset dev flags 0x12`. The memory
response then timed out (`err = -110`). No target-capability
exchange, no TME-Lite request, no `wlan`. Hyprland stayed
active. oops count 0. ath12k is bound.

Type 1 is host DDR, type 4 is calibration data, type 11 is
LPASS shared. The allocation for type 11 was already in the
driver. This probe is the one that shows the firmware asks
for it.

## Learning

A 36-bit window is not what stock sends. Stock's peach node
uses a few hundred megabytes. The on-disk module is the
follow-up that keeps the segment log and does not send
`ddr_range`. It is not loaded. Do not `insmod` ath12k again
on this boot.
