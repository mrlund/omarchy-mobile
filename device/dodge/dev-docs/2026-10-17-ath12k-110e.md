# 2026-10-17 — ath12k claims 17cb:110e and stops on the version

**Goal.** Let ath12k bind the endpoint and see which hardware
version it reports, before any firmware is sent.
**Phone.** OnePlus 13 CPH2653. The desktop stayed up.
**Kernel.** `6.16.0-gb3ee311dab85`
**Result.** The chip reports WCN7850 hw2.0 once the window register
is `0x3278`. QMI is not up, so there is still no wireless interface.

## What we did

`pci.c` now lists `0x110e` next to the WCN7850 id and uses that
path. The module was built for the running kernel and insmodded
after `rfkill`, `libarc4`, `cfg80211`, `mac80211`, `mhi` and
`qmi_helpers`. The phone has no `ath12k` firmware directory.

## What happened

```
ath12k_pci 0000:01:00.0: BAR 0 [mem 0x40400000-0x405fffff 64bit]: assigned
ath12k_pci 0000:01:00.0: enabling device (0000 -> 0002)
ath12k_pci 0000:01:00.0: Unknown hardware version found for WCN7850: 0xf
ath12k_pci 0000:01:00.0: probe with driver ath12k_pci failed with error -95
```

The first read, through window register `0x310c`, is `0xffffffff`.
Major `0xf` is just bits 11:8 of that empty value. BAR 0 offset 0
reads `0x00000100`, so the BAR itself is alive. The other window
register, `0x3278`, returns `0x40210200`, which is SOC major 2.
With that register selected the driver prints `Hardware name:
wcn7850 hw2.0` and allocates 16 MSI vectors.

QMI init then returns `-517` (`-EPROBE_DEFER`). `qrtr` was not
loaded. The failure path oopses in `qmi_handle_release`, and the
driver stays bound, so it cannot be unloaded on this boot. `qrtr`
and `qrtr-mhi` are loaded now. The upstream WCN7850 hw2.0 files
(`amss.bin`, `m3.bin`, `board-2.bin`) are on the phone under
`/lib/firmware/ath12k/` and were not requested. ath12k is not
started at boot.

## Learning

`17cb:110e` is this chip's PCI id for a WCN7850 hw2.0, reached
through window register `0x3278`. The next probe has to load `qrtr`
before ath12k, and it has to be a fresh bind. The oops on the
defer path is a separate bug.
