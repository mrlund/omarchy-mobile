# 2026-10-17 — stock WLAN PDC messages

**Goal.** Send stock's `qcom,pdc_init_table` to the AOSS before
WLAN enable, and see if TME-Lite error 83 changes.
**Phone.** OnePlus 13 CPH2653. One restart so the messages
could go out before the chip was enabled. Desktop stayed up.
**Kernel.** `6.16.0-gb3ee311dab85`
**Result.** Fail. The AOSS acknowledged all four strings.
TME-Lite is still `result 1, err 83`. No `wlan`.

## What stock has

`cnss-peach` points `qcom,qmp` at `aoss_qmp` and lists:

```
{class: wlan_pdc, ss: rf, res: s5f.m, enable: 1}
{class: wlan_pdc, ss: rf, res: s5f.v, enable: 1}
{class: wlan_pdc, ss: rf, res: s5f.v, upval: 876}
{class: wlan_pdc, ss: rf, res: s5f.v, dwnval: 876}
```

There is no `qcom,vreg_ol_cpr`. The AOSS debugfs files cannot
send an arbitrary string. `qmp_send()` can.

## What the phone did

Each send returned 0, before `wlan-en` went high. The endpoint
came up. The 28-bit DMA mask was still in effect, and the
three memory segments landed at `0x0e800000`, `0x0e400000` and
`0x0e3ff000`. Target cap reported the peach build. TME-Lite
failed, the firmware reset about 200 ms later, and mode 7
timed out. Hyprland stayed active. oops count 0. ath12k is
bound. Do not load it again on this boot.

The Wi-Fi PCIe service is enabled again. It still does not
load ath12k.
