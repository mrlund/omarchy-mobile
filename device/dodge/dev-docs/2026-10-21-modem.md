# 2026-10-21 — modem assessment (MPSS, rmtfs, IPA, ModemManager)

**Goal.** Find out what the modem DSP needs on sm8750-mainline 6.16 before
ModemManager can see a modem. Root cause first, no boot yet.
**Phone.** OnePlus 13 CPH2653 (dodge). No serial, IMEI, IMSI or number here.
**Kernel.** `6.16.0-gb3ee311dab85` (Oct 16 Image plus later modules).
**Result.** Stopped after the assessment. The modem firmware is staged on the
phone. Nothing was booted, flashed or started, and the modem stays down.

## What we did

- Read the kernel tree, the dodge DTS, the stock live DT
  (`rooted-2026-10-15-on/live.dts`) and the stock boot log. All read-only.
- Mounted `modem_a` (vfat, `sde6`) **read-only** on the phone and copied
  `image/modem.mdt` to `/lib/firmware/qcom/sm8750/OnePlus/modem.mbn`, the
  `modem.bNN` segments (42), `modem_dtb.mdt` as `modem_dtb.mbn` with its 3
  segments, and `image/modem_pr/` (MCFG carrier configs, 30 MB) the same way.
  That is 72 MB. Unmounted afterwards. The ADSP was done the same way
  (2026-10-19). Not committed.
- Checked the partition names: `modemst1`, `modemst2`, `fsg` and `fsc` exist
  (`sdf10`-`sdf13`), and so do the OnePlus NV partitions `oplusdycnvbk` (`sdf7`)
  and `oplusstanvbk_a` (`sdf8`). **None of them was opened.**

## What we found

| Piece | State on 6.16 | Needed |
|---|---|---|
| `remoteproc_mpss` DT | In `sm8750.dtsi`, enabled in the dodge DTS with `modem.mbn` / `modem_dtb.mbn`. Same `mpss_mem` (`0x8ba00000`, 246 MiB) and `q6_mpss_dtb_mem` as stock. | Nothing |
| `qcom_q6v5_pas` | `sm8750_mpss_resource` exists (pas_id 4, dtb 0x26, DSM regions assigned to MSS_MSA at probe, `auto_boot` false). | Load with `only_adsp=0`; start by hand through sysfs |
| Firmware | Staged on the phone (above). | Nothing |
| `rmtfs_mem` | **Missing** from `sm8750.dtsi` and the dodge DTS. Stock uses a 4 MiB `qcom,sharedmem-uio` region, `client-id` 1, allocated at boot. `sm8650.dtsi` has the upstream form (`qcom,rmtfs-mem`, `qcom,vmid` MSS_MSA). | A static 4 MiB `rmtfs_mem` carve-out in the dodge DTS at a free address: a DTB change and a boot |
| rmtfs userspace | **Not installed.** Stock's `rmt_storage` serves `modemst1/2`, `fsg`, `fsc`, **and** OnePlus's `oplusdycnvbk`/`oplusstanvbk`, read-write. | `rmtfs` **never with `-P`** (real partitions). Serve copies from a scratch directory in a read-only mode, so the modem can't write EFS or NV |
| tqftpserv | Not installed. Stock runs `tftp_server`; the modem reads MCFG from it. | `tqftpserv`, pointed at the staged `modem_pr` |
| QRTR, PD mapper | In the kernel (`QRTR`, `QRTR_SMD`, `QCOM_PD_MAPPER` with the SM8750 list from `0021`, `SYSMON`, `PDR`). Already used by the ADSP. | Nothing |
| IPA (data) | Stock `qcom,ipa-hw-ver` is `0x18`. The 6.16 `ipa` driver knows nothing newer than `sm8550-ipa` (v5.5), and there is no IPA node in `sm8750.dtsi`. | Later. Calls and SMS are QMI over QRTR and don't need IPA. Mobile data does |
| `rmnet` | `RMNET=m` | With IPA |
| ModemManager, libqmi | **Not installed.** pacman on the phone can't verify `omamobile` (`keyring is not writable`, no `pacman-key --init`). | Fix the keyring, then `modemmanager` and `libqmi` with QRTR support |
| Call audio (q6voice) | Not in this tree. AudioReach voice graphs are a project of their own. | Last |

## Risks found

- **rmtfs is the only way the modem writes EFS or NV.** Upstream rmtfs with
  `-P` writes `modemst1`/`modemst2`/`fsg`/`fsc` on request, and OnePlus adds two
  more NV partitions. That is the calibration/EFS the rules forbid touching.
  The plan is to run rmtfs only on in-RAM copies with writes dropped. Check
  rmtfs's options in the installed version first; if it can't drop writes,
  serve copies in a tmpfs and never point it at `/dev/sdf*`.
- PLAN §6 row 11 asks for NV backups first. Reading `modemst1/2`, `fsg` and
  `fsc` is allowed, but the copies contain the IMEI and NV. They stay off git
  and off this repo (owner-only, mode 600).
- Starting the modem without rmtfs makes it wait or crash. A crash is a
  remoteproc recovery, not a reboot, but a fatal error can take the SoC down,
  so the log stream and the watchdog stay on.

## Learning

Next, one change per boot:

1. Fix the phone's pacman keyring. Install `rmtfs`, `tqftpserv`, `qrtr`
   tools, `libqmi` and `modemmanager`, all disabled. No boot.
2. Make read-only copies of `modemst1`, `modemst2`, `fsg` and `fsc` into
   `/var/lib/omamobile/modem-efs/` (mode 600) for rmtfs to serve. Not committed.
3. DTS: add a 4 MiB `rmtfs_mem` (`qcom,rmtfs-mem`, client-id 1, vmid
   MSS_MSA) in a hole of the stock memory map. Build the DTB, `fastboot boot`
   first, then flash `boot_a` and `set_active a`.
4. Boot with `only_adsp=0`. Start rmtfs (copies, read-only) and tqftpserv, then
   `echo start > /sys/class/remoteproc/remoteprocN/state`. Watch for `running`
   and the modem's QRTR services (`qrtr-lookup`).
5. `qmicli -p -d qrtr://0 --uim-get-card-status` for the SIM, then
   ModemManager `mmcli -L`. Redact any IMEI, IMSI or ICCID. Calls and SMS wait
   for Martin.
