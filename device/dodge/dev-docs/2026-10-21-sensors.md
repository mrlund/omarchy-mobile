# 2026-10-21: sensors (accelerometer, proximity, compass) through the ADSP SSC

Times are CEST. Overview: [../sensors/README.md](../sensors/README.md).

## Root cause
- SSC (QMI 400) is already up on the ADSP (QRTR node 5) on every boot. On stock,
  `adspslpi_mem` is used, so the SLPI is merged into the ADSP.
- libssc `ssccli` before this work: the `registry` sensor was never available. The sensors
  PD waits for an APPS-side FastRPC file server, which is hexagonrpcd. No kernel
  change was needed. `/dev/fastrpc-adsp-secure` is enough. There is no
  non-secure node because the DT lacks `qcom,non-secure-domain`.

## Steps
1. libssc 0.4.4 (codeberg, 4e4c6c8) built on the phone without GIR.
2. hexagonrpc (linux-msm, da7a374) built. Root dir with read-only copies:
   - persist `sensors/registry/registry`: 751 files, already parsed by Android;
   - `dsp_a/adsp`;
   - vendor `etc/sensors/config`: 146 JSON, and `sns_reg_config`;
   - odm `etc/sensor/config`: 19 OPlus JSON.
   Vendor and odm come out of `super`: the LP metadata is parsed by
   `lp-extents.py`. This kernel has no device-mapper or erofs, so the extents
   are dd-copied into an image and extracted with `fsck.erofs`.
3. First attach: the registry became available, but there was no accel sensor.
   The DSP looked for `/odm/etc/sensor/config/json_list`, and socinfo was
   empty. Fixed with an odm mapping patch and stub socinfo
   (MTP/618, matching the odm JSON).
4. The sensors PD only initialises on its first attach in each ADSP boot, so
   I added `omamobile-sensors.service` and rebooted (sensors-1, 12:01, gated
   on charging). It failed at first because `libhexagonrpc` wasn't installed.
   I installed it and started the service, which counted as the first attach:
   **accel X=0.01 Y=0.39 Z=9.72 m/s²** (phone flat), proximity
   NEAR/FAR. hexagonrpcd then exited on "Unsupported method 36".
5. Patched the listener to return AEE_EUNSUPPORTED and keep going. Reboot
   sensors-2 (12:05): the service keeps running, and accel and prox still
   work. The DSP keeps asking for `/proc/oplusVersion/pcbVersion` and a few
   camera/ODP files, which don't matter.
6. iio-sensor-proxy (git ca0d5b0) with `ssc-support=enabled`, plus a udev
   rule: `monitor-sensor` shows accelerometer (tilt face-up), proximity and
   compass. "No ambient light sensor".
7. Hyprland 0.56 uses the Lua config: `hyprctl keyword` is refused, so I use
   `hyprctl eval "hl.monitor({... transform = N})"`.
   Sensor claims need the active session, so autorotate must be started from
   Hyprland and not from ssh or a systemd user unit.

## Checks on both boots
EFS unchanged, modem condition-skipped, MM and netport skipped (`ConditionResult=no`),
`rmnet_mm0` absent, display errors 0, audio, Wi-Fi and BT fine, ADSP running.

## Open
- Ambient light: `ambient_light` isn't discovered. OPlus probably uses its own
  type (`alsps_platform`, `lux_aod`), and under-display ALS likely needs
  brightness/frame input from the display. Next: list all SUIDs (registry
  sensor or a small libssc discovery for every data type).
- Auto-rotate mapping (left-up → 1, right-up → 3) still needs a check with the
  phone in hand. Opt-in for now.
- Power cost of a running sensors PD and hexagonrpcd: not measured.
