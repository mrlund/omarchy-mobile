# 2026-10-17 — PCIe is up, the Wi-Fi chip is not powered

**Goal.** Enumerate the Wi-Fi device without the panel driver.
**Phone.** OnePlus 13 CPH2653. Omarchy 4.0.4. Hyprland stayed up.
**Kernel.** `6.16.0-gb3ee311dab85`
**Result.** The PCIe root port bound. No endpoint appeared.

## What we did

`1c00000.pcie` was deferred with an empty reason. Its PHY is
`qcom,sm8750-qmp-gen3x2-pcie-phy`, and
`CONFIG_PHY_QCOM_QMP_PCIE=m`, so the module was sitting in the held
tree. `insmod phy-qcom-qmp-pcie.ko` only. ath12k was not loaded.
The module is not installed for the next boot.

## What happened

`qcom-pcie` bound. `lspci` shows only `17cb:011c`, the root port.
Link status is 2.5 GT/s, width 1. The port driver's MSI setup warned
in `its_build_mapti_cmd` (device id 0) and bailed out. The session
stayed up. `vdda` and `vddpe-3v3` on the host are dummy regulators.

The endpoint in the board file is `pci17cb,1107` (ath12k's WCN7850
id). The power node next to it is `qcom,wcn7880-pmu`, status
disabled, with the comment "No compatible drivers". Its supplies
match the upstream `qcom,wcn7850-pmu` set (`vdd`, `vddio`, `vddaon`,
`vdddig`, `vddrfa1p2`, `vddrfa1p8`) plus `vddio1p2`. Stock's CNSS
node was `qcom,cnss-peach` with `supported-ids = <0x110e>`, which is
not the PCI id 0x1107. Nothing enables `wlan-enable-gpios` on tlmm
16, so the chip stays off the bus.

## Learning

The missing piece is the radio's power sequencer, not ath12k and not
the panel driver. `pwrseq-qcom-wcn` knows `qcom,wcn7850-pmu` and does
not know `qcom,wcn7880-pmu`. Powering that node is a separate boot,
after the compatible and the extra `vddio1p2` supply are settled.
The ITS warning is the next problem once a device actually
enumerates.
