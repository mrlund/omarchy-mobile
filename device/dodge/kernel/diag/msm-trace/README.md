# msm first-commit trace and splash stop (Round 13, 2026-10-22)

DIAG only, 6.16 (`omamobile-dodge`). Not for upstream. Built as `msm.ko`, tested one boot at a time.

- `0001-DIAG-drm-msm-...patch`: the local kernel commit. It adds `dodge_trace.c`/`.h` plus hooks in msm_mdss, msm_kms, dpu_kms, dpu_hw_ctl, dpu_hw_intf and dsi_host, then `dodge_stop_splash()` before `msm_mdss_reset`, then a 1:1 read-only map of the splash reserved region in the display domain.
- `91-dodge-oneshot.conf`: drop-in for `omamobile-display-msm.service`. Put a module at `/root/msm.oneshot.ko` and it is used for **one** boot only, then moved to /run. A module that hangs the phone is gone after the reboot.
- `rbo.sh TAG KO [N]`: stages the one-shot, does a gated warm reboot (`/tmp/rbt.sh`) and prints the summary. `loop.sh KO FIRST LAST`: consecutive one-shot boots plus `dp.sh`, stopping at the first bad boot.
- `dp.sh` (runs on the phone): 3 screen off/on cycles with `omarchy-brightness-display`, then a 165 s wait for the idle-off, then a wake. Prints dpms and the tx-failed delta. Note that `hyprctl dispatch dpms` is Lua syntax on this Hyprland.
- `rescue-initramfs.sh`: boot-loop rescue. Pipe it into the stage-2 initramfs dropbear during its short window (about 4-6 s after the USB gadget appears). It mounts userdata and copies `msm.ko.pre-trace` over `msm.ko`.

Rule learned the hard way: any MDP/DSI MMIO read must check the GDSC **and** the branch CBCR CLK_OFF bits (dispcc 0xaf00000: ahb 0x80b0, mdp 0x8010, byte0 0x8034, esc0 0x8044). Right after the BCR, ahb/mdp read 0x88000001 (off), and a read then hangs the bus (boot loop).
- `rbt.sh TAG`: battery gate (full-battery rule), warm reboot, saves logs/m-TAG.txt and the kernel journal. It replaces the lost /tmp/rbt.sh.
- `../panel-rail/`: the Round 15 panel rail-cycle diag patch, the one-boot panel drop-in `92-dodge-panel-oneshot.conf`, and `rbp.sh TAG KO` to stage it.
- `0007-tpg-fifo-resend-and-vbif-halt-dump.patch`: Round 17. On the first -110, sw reset and resend through the TPG DMA FIFO (no memory fetch). Later commands of 64 bytes or less use the FIFO after a success. VBIF XIN/AXI halt dump at the BCR, first command and -110. Applies on top of the revert of 0006.
- `0008-r18-first-dma-dumps-iova-fifo-depth.patch`: Round 18. VBIF+STATUS0 at first-trig/first-done, dma_base iova vs iommu_iova_to_phys, and a no-trigger TPG FIFO depth probe. On top of 0007.
- `0009-r18b-dma-count-shift.patch`: Round 18b. Resends the first panel command twice (DMA count-shift test). On top of 0008.
- `0010-r19-fifo-first-two-mem-dma.patch`: Round 19. On OnePlus,13 only, every DSI command of 64 B or less goes through the TPG FIFO from the first command, and memory DMA is used only for longer ones (0x81, PPS), each logged. On top of 0008 (0009 reverted). Not a workaround: on a bad boot the PPS DMA hangs.
- `loop19.sh FIRST LAST`: r19 one-shot warm boots until a c60 or failing boot (installed as /tmp/loop19.sh).
- Hard deadline for diag boots: `93-dodge-deadline.conf` (drop-in, runs `/root/dodge-deadline-arm.sh` before msm loads) arms a `systemd-run --on-boot=240` reboot timer (CLOCK_MONOTONIC since kernel boot, DefaultDependencies=no, so a late start cannot push it out) whenever a one-shot module is taken or `/root/dodge-deadline` exists. `dodge-deadline-check.sh` runs at 80 s uptime and cancels it only on a clean boot (no tx failure / panel init failure / frame-done or kickoff timeout, dpms On). Host side, `rbt.sh` runs every SSH call under `timeout`, caps the SSH wait, and on a bad boot (tx failed, panel init failed, kickoff timeout, 5+ frame-done timeouts or dpms not On) runs `HOOK` (optional phone script, 20 s) and does an immediate gated reboot. `rbo.sh` wraps it in `timeout 420`.
- `0011-r20-qtb-ot-snapshot-readonly.patch`: Round 20. Strictly read-only dump of the display QTB500s (mdp_hf_qtb 0x17d0000, sf_qtb 0x17d1000): SWID_LOW 0x0, FENCEREQ 0x410, FENCEACK 0x418, OT_SNAPSHOT port 0/1 0xc10/0xc20 (offsets from the OnePlus sm8750 downstream arm-smmu-qcom.c qtb500 impl) at every VBIF dump point. On top of the revert of 0010 (r18 state). `0012` (r20b): no QTB reads at the mdss-* points. `0013` (r20c): mapped, never read. `0014` (r20d): one SWID_LOW read at first-cmd only. `0015` (r20e): timing control, dsb + udelay(5) + pr_info at that point, no QTB access. `0016` (r21a): one sf_qtb SWID_LOW read at first-cmd only (hf vs sf).
- `loop20.sh FIRST LAST` (env `V=` variant dir under msm-variants, `P=` tag prefix): one-shot warm boots until a DSI failure; prints the last QTB line per boot (installed as /tmp/loop20.sh).
- `loop20x.sh N VAR:TAG VAR:TAG ...`: interleaved A/B one-shot boots (N rounds, one boot per arm per round), so arms see the same drift.
- `idcheck.sh`: identifier scan of the unpushed diff (MACs, IMEI, ICCID, phone numbers, psk/password, the phone USB serial from host sysfs, and private regexes from ~/.config/omarchy-mobile/private-ids outside the repo). Prints counts only, exits 1 on a hit; push only if it exits 0.
- `fresh-consult-facts.md`: the fact sheet given to a fresh, theory-free consult (2026-10-23).
